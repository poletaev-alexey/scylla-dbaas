# Where the AI was wrong

| # | What happened | How it was caught | Fix |
|---|---|---|---|
| 1 | Enum-typed columns were declared as `String`, so values came back as `str` and every `status is ClusterStatus.X` check was silently false (7 of 13 tests failed). | First test run. | `enum_col()` helper using SQLAlchemy `Enum(native_enum=False)`. |
| 2 | After `session.rollback()` the code read attributes of expired ORM objects; async SQLAlchemy cannot lazy-load, so the failure handler itself crashed and a Cluster stayed `provisioning` instead of `failed`. | Test `test_failed_provisioning_marks_cluster_failed` + a "coroutine never awaited" warning. | Cache ids before handlers run; `refresh()` after rollback. |
| 3 | Race: when Auto-recovery cancelled a Backup during a `commit()` that sat outside the `try`, the Backup row stayed `running` forever. Tests passed 8/10 times. | Running the suite in a loop (10×) instead of trusting one green run. | Whole Backup body inside `try`; failure marked via a fresh session; verified 30/30. |
| 4 | Plan deck was started before the code, but the human wanted code first ("может код сначала?"). | Human interrupted mid-turn. | Deck paused at 7/13 slides; code work started. |
| 5 | API returned naive timestamps (SQLite drops tz) and 409s without the documented `active_operation_id`. The orchestrator's own tests didn't check either. | The **UI agent** reported both while integrating against the real API — a reviewer found by a consumer, not by the author. | `UTCDateTime` column type; global `OperationConflict` → `Problem` handler; tests assert both. |
| 6 | Contract flaw by the orchestrator: `recreate_monitor` returned only `NodeInfo`, so the handler guessed Grafana/Manager URLs as `http://<ip>:3000` — wrong for the local driver (ports published on 127.0.0.1). | Reported by the scylla-ops-local agent, which implemented around it as instructed instead of silently changing the contract. | Contract now returns `ClusterInfra`; fake, local and handler updated; AWS agent notified mid-flight. |
| 7 | Orchestrator reported "installed Terraform" because the background install exited 0 — but the exit code was `tail`'s; brew had failed (outdated Xcode CLT). The infra agent silently worked around it with its own scratchpad binary. | Merge-time verification: `terraform validate` → "command not found". | Downloaded the official binary with SHA256 check to `~/.local/bin`. Lesson: `set -o pipefail`, verify tools with `which` after install. |
| 8 | The `local` driver had never started three Scylla containers at once: the third Data Node crashed with "does not satisfy minimum AIO requirements" (Docker Desktop's VM has `fs.aio-max-nr` = 65536) and the Operation timed out after 15 min. Unit tests with a fake `docker` could not see it. | First real run of the integration test once the human started Docker Desktop. | Driver raises `fs.aio-max-nr` in the Docker VM with a privileged one-shot container before starting nodes. |
| 9 | One-shot Manager tasks (Backup, Restore, Repair) were created with `start_date = now`, which the code comment claimed matched `sctool`. Manager 3.13 drops a one-shot start date that is already past when the scheduler sees it: the Backup sat in `NEW` forever ("no activations scheduled"). The mocked Manager accepted it. | Second integration run; diagnosed with `sctool info`, confirmed by starting the stuck task by hand (it then finished and uploaded to S3). | Tasks are created with no trigger and started with `PUT …/start`; the unit test now asserts that. Lesson: a mock encodes the author's belief about the API, so it cannot catch a wrong belief. |
| 10 | The integration test called `DELETE /clusters/{id}` without `?confirm=<name>`, a rule added later; nothing ran that test in between. | Third step of the same integration run (422). | Test fixed. |
| 11 | cloud-init pinned `scylla-node-exporter` to the ScyllaDB version, but that package is versioned independently (`1:1.12.1-1`): `apt-get` failed on every Data Node. Only `bash -n` and `terraform validate` had checked the script. | First AWS run; bootstrap log read over SSM. | Pin `scylla`, `-server`, `-conf`, `-kernel-conf`, `-python3`, `-cqlsh`; install node-exporter unpinned. |
| 12 | Monitor Node: `scylla-manager-db` restarted forever with `PermissionError: /var/lib/scylla/data`; the `scylla` image runs as uid 998 and the bind-mounted host dir was root-owned. | Same run, `docker logs` over SSM. | Named Docker volume; fix confirmed on the live node before changing the template. |
| 13 | Terraform race: the Monitor Node's EIP was associated with its ENI while the instance was `pending` → `IncorrectInstanceState`. The first run won the race by luck. A hand-written watcher also hid the failure (it never printed the terminal state). | Second AWS run failed; watcher rewritten to always print the final status. | `depends_on = [aws_eip.node]` on the Monitor instance. |
| 14 | Seed deadlock: seeds were `data-1,data-2`, but `data-2` waits for `data-1` to serve CQL, and with Raft topology `data-1` waits for every listed seed. `data-1` sat in `STARTING`. The ADR-era design note even recommended two seeds. | Third AWS run; `scylla.yaml` + journal over SSM; confirmed by making `data-1` the only seed (needed a data wipe because discovery state was already persisted). | Seed = `data-1` only on creation; replacing nodes still use the two live peers. |
| 15 | Manager registration failed: a node served CQL a few seconds before its Manager Agent listened on :10001, and Manager rejects a Cluster if any Agent is unreachable. | Third AWS run. | Registration retries the "connectivity check" error; unit test added. |
| 16 | After a Control Plane restart the stale Operation was marked failed but its Cluster stayed `provisioning` forever (and so could not be deleted cleanly). | Noticed while restarting the API during the AWS run. | Restart recovery moves `provisioning`/`deleting` → `failed`, `recovering` → `degraded`; test added. |
